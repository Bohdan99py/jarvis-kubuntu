# Jarvis Desktop 0.20.0 — выпуск стабилизации рабочего стола

## Установка

```sh
sudo apt install ./jarvis_0.20.0_ubuntu-26.04_amd64.deb
```

Пакет только добавляет файлы (программы, виджеты Plasma, модуль `org.jarvis.visual`, службы systemd user) и включает пользовательскую службу глобально. Раскладку рабочего стола, панели и настройки KDE он не трогает. JARVIS DESKTOP включается отдельно: «Центр управления → Рабочий стол» или `jarvis --desktop-mode jarvis`.

## Обновление с 0.19.x

Та же команда `sudo apt install ./jarvis_0.20.0_….deb`. После установки новые файлы виджетов подхватит только новый процесс plasmashell. Достаточно выйти из сеанса и войти снова. Можно и без выхода, из терминала (окна программ не закрываются):

```sh
systemctl --user restart plasma-plasmashell.service
```

Повторно включать JARVIS DESKTOP не нужно. Повторное включение ничего не дублирует: проверено тестом `desktop_shell_session`.

Новое поведение панели (стекло под треем и часами, прокрутка программ) работает сразу. Выключить стекло: правый щелчок по доку → «Настроить виджет „Док Jarvis“…» → «Панель» → «Стекло Jarvis под всей панелью».

## Откат

- **К стандартному KDE** (раскладка до JARVIS DESKTOP): «Вернуть стандартный KDE…» в Центре управления или `jarvis --restore-desktop`. Plasmashell перезапускается, раскладка возвращается из первой резервной копии в `~/.local/share/jarvis/desktop-backup/`. Текущая раскладка перед этим сохраняется в `before-restore-…`.
- **К предыдущей версии пакета:** `sudo apt install ./jarvis_0.19.3_ubuntu-26.04_amd64.deb` (лежит в `dist/`). Затем повторный вход или `systemctl --user restart plasma-plasmashell.service`. Настройки и память Jarvis не меняются. Опция стекла `panelStyle` останется в конфигурации дока, но 0.19.3 её просто не читает.
- **Если plasmashell не запускается** (крайний случай): из консоли (Ctrl+Alt+F3) выполнить `jarvis --restore-desktop`; если не помогло — `plasmashell --replace &`.

## Известные ограничения

- Проверка шла на виртуальных экранах вложенного KWin, а не на вашем ноутбуке и его видеокартах. Пакет в настоящую систему не ставился: только во временный корень и через `apt-get -s` (симуляция).
- Подключение и отключение второго монитора на ходу и смена основного экрана не проверены: виртуальный KWin так не умеет. Ручная проверка — ниже.
- Док ставится на один (первый) экран. Настройка `dockAllScreens` в конфигурации пока ничего не делает.
- Кнопки пространств GENERAL/STUDY/WORK/DEV появляются, только когда отвечает `jarvisd`: при запуске или остановке службы док меняет длину.
- Цвета трея и часов на стекле — дополнительная (Complementary) схема темы Plasma. Окна, которые открываются из трея (громкость, сеть, календарь), остаются в обычной теме Plasma: это штатные окна.
- Тёмная тема и автоскрытие проверены только вручную во вложенном сеансе, автотеста для них нет. Если включить автоскрытие на ходу у уже использованной панели, она остаётся видимой, пока указатель не войдёт в неё и не выйдет. Так же ведёт себя обычная панель Plasma (проверено рядом), это не поведение дока.
- Полная переработка настроек запланирована отдельно; в 0.20 исправлены только явные проблемы подписей.
- Kubuntu 24.04 (Plasma 5.27): док и JARVIS DESKTOP требуют Plasma 6, как и раньше.

## Ручная проверка на настоящем рабочем столе

1. После обновления выйти из сеанса и войти. Правая часть панели (трей, часы) — на том же тёмном стекле, что и док; значки трея и часы светлые.
2. Щёлкнуть громкость, сеть, Bluetooth, «^» (скрытые значки), часы. Окна открываются над панелью и целиком на экране.
3. Закрепить 20–30 программ (или поставить панель слева). Трей и часы остаются на экране, программы прокручиваются колесом.
4. Подключить второй монитор, сменить основной экран в «Параметрах системы → Экраны», отключить внешний монитор. Док остаётся на экране, «Пуск» открывается у кнопки.
5. `systemctl --user stop jarvis.service jarvis-tray.service`. «Пуск» (щелчок и Meta), запуск программ и переключение окон работают. Затем `systemctl --user start jarvis-tray.service`.
