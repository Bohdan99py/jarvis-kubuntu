# Jarvis Desktop 0.21.0 — понятные настройки

## Установка

```sh
sudo apt install ./jarvis_0.21.0_ubuntu-26.04_amd64.deb
```

Пакет добавляет и заменяет только файлы Jarvis (программы, виджеты Plasma, модуль `org.jarvis.visual`, службы systemd user). Новых зависимостей нет. Рабочий стол, панели и настройки KDE при установке не меняются.

После установки перезапустите Jarvis: «Выход» в меню трея, затем запуск из меню приложений. Службу перезапускать вручную не нужно: при первом запуске окна или службы настройки обновятся сами. Новые файлы виджетов (подписи в настройках дока) plasmashell подхватит при следующем входе в сеанс или после `systemctl --user restart plasma-plasmashell.service`.

## Где что настраивается

Окно «Настройки Jarvis»: меню Jarvis → «Настройки…», трей → «Настройки…», `jarvis --open settings` или `jarvis --open settings:<раздел>` (`desktop`, `conversation`, `intelligence`, `privacy`, `actions`, `skills`, `system`).

| Раздел | Что внутри |
|---|---|
| Рабочий стол | JARVIS DESKTOP; тема, цвета, свечение, прозрачность, скорость, размер элементов, качество, ядро; вид окна Jarvis; док (край, высота, выравнивание, автоскрытие, значки, увеличение, стекло, кнопки); панели и виджеты; рабочие пространства |
| Общение с Jarvis | язык интерфейса и ответов; голос (озвучивание, движок, темп, ElevenLabs, Chatterbox, Piper); диктовка и микрофон; горячие клавиши; чат и оверлей; напоминания и уведомления |
| Интеллект и подключение | ключ API Claude, модель, «Сохранить», «Проверить подключение», веб-поиск, что работает без ключа и интернета |
| Память и приватность | что хранится и что отправляется; обучение, любопытство, пересмотр памяти, панель памяти; активность; окно, экран, снимки в Claude, фоновый анализ, исключённые программы, пауза; удаление данных по видам |
| Действия и разрешения | уровень инициативы; лимиты и виды предложений помощи; подсказки, перерывы, утренний план; виджеты и KRunner; что Jarvis всегда спрашивает |
| Навыки | навыки, импорт |
| Система и восстановление | автозапуск, фоновая работа; версии и службы; диагностика; видеокарта и графический API; обновления; модули KDE; сброс; возврат к стандартному KDE; файлы настроек и откат |

**Поиск** — Ctrl+F в окне. Работает на этом компьютере, без интернета и без модели. Примеры: «наушники», «звук» → «Звук: динамики, наушники и микрофон»; «кнопки», «сочетания» → горячие клавиши; «ключ», «API», «подключение» → Claude; «запоминать», «история» → память.

**Когда применяется.** Переключатели, списки и ползунки — сразу. Ключ, модель, исключённые программы — кнопкой «Сохранить» (с проверкой). Видеокарта и графический API — после перезапуска Jarvis (строка помечена «↻»), автозапуск — при следующем входе. Ошибка сохранения показывается под строкой; элемент остаётся с прежним значением, введённый текст не стирается.

**Что открывает KDE** (кнопка «Открыть в KDE», есть только при установленном модуле): Звук (`kcm_pulseaudio`), Bluetooth (`kcm_bluetooth`), Сеть и Wi-Fi (`kcm_networkmanagement`), Экраны и масштаб (`kcm_kscreen`), Питание (`kcm_powerdevilprofilesconfig`), Уведомления (`kcm_notifications`), Комбинации клавиш (`kcm_keys`), Клавиатура (`kcm_keyboard`), Глобальная тема (`kcm_lookandfeel`), Регион и язык (`kcm_regionandlang`), Автозапуск (`kcm_autostart`). Запуск — `systemsettings <модуль>`, без него `kcmshell6`/`kcmshell5`.

## Обновление с 0.20 и миграция

При первом запуске 0.21 (окна или службы — что раньше, второй ждёт):

1. Копия `~/.config/jarvis/config.json` сохраняется в `config.json.backup-v1` (0600). Ключ в неё не пишется, если он переезжает в хранилище паролей.
2. Ключи Claude (`config.json`) и ElevenLabs (`~/.local/share/jarvis/voice/speech.json`) записываются в системное хранилище паролей. Из файлов они убираются только после того, как прочитаны обратно из хранилища. Если хранилища нет, ключи остаются в файлах.
3. В config.json появляется `"config_version": 2`. Все прежние значения, закреплённые программы, раскладка, память и история остаются. Поля, которых эта версия не знает, сохраняются и дальше при каждой записи.
4. Повреждённый config.json не перезаписывается: он переименовывается в `config.json.damaged-<дата-время>`, Jarvis начинает с настроек по умолчанию.
5. Повторный запуск ничего не меняет. Что сделала миграция — в журнале (`journalctl --user -u jarvis | grep settings:`) и внизу раздела «Система и восстановление».

Разрешения при миграции не расширяются: значения переносятся как есть, новых включённых разрешений нет.

## Откат к 0.20

1. **До** установки старого пакета выполните `jarvis --prepare-downgrade` (Jarvis 0.21 должен быть ещё установлен). Ключи из хранилища вернутся в config.json и speech.json, файл получит версию 1. Если хранилище заблокировано, команда так и скажет: откройте настройки Jarvis, разблокируйте и повторите.
2. `sudo apt install ./jarvis_0.20.0_ubuntu-26.04_amd64.deb`, затем перезапуск Jarvis (и повторный вход для виджетов).
3. Если шаг 1 пропущен, 0.20 просто попросит ключ заново («Настройки Claude API»); остальные настройки 0.20 прочитает как есть. Ключи остаются в хранилище паролей, их можно удалить в KWalletManager (записи «Jarvis: Anthropic API key», «Jarvis: ElevenLabs API key»).
4. Резервная копия настроек до 0.21 — `~/.config/jarvis/config.json.backup-v1`. Чтобы вернуть именно её: `cp ~/.config/jarvis/config.json.backup-v1 ~/.config/jarvis/config.json` (ключа в ней нет, если он переехал в хранилище).

Повторное обновление до 0.21 снова перенесёт ключи.

## Сброс и удаление данных

- «Сбросить эту страницу…» — настройки текущего раздела; «Сбросить все настройки…» — всех разделов. Перед сбросом показан список того, что изменится.
- Сброс не трогает память, историю разговоров, ключи API, закреплённые программы, раскладку рабочего стола и режим JARVIS DESKTOP. Разрешения сбросом не включаются, исключённые программы остаются исключёнными, уровень инициативы не повышается.
- Удаление данных — в «Памяти и приватности», по видам, у каждого своё подтверждение.
- Возврат к стандартному рабочему столу KDE — «Система и восстановление → Вернуть…» или `jarvis --restore-desktop` (как в 0.20).

## Команды

- `jarvis --open settings[:раздел]` — открыть настройки (в работающем Jarvis — через D-Bus).
- `jarvis --settings-search <слова>` — тот же поиск, что в окне, вывод в терминал.
- `jarvis --prepare-downgrade` — перед установкой версии старше 0.21.

## Ограничения и что не проверено

- **Настоящее хранилище паролей (KWallet/ksecretd) не трогалось**: код Secret Service проверен на поддельной службе с тем же протоколом. Перенос ключа в ваш KWallet произойдёт при первом запуске 0.21 — проверьте «Интеллект и подключение»: должно быть «Сохранён (…) в системном хранилище паролей».
- Проверка шла во вложенной Plasma на виртуальных экранах, а не на вашем рабочем столе и видеокартах; пакет в систему не ставился (только временный корень и `apt-get -s`).
- Сборка для Ubuntu 24.04 (Qt 6.4, Plasma 5.27) локально не проверялась — её проверит CI при отправке в main. Док и JARVIS DESKTOP на Plasma 5 по-прежнему недоступны.
- Чтение экрана во время отключения разрешения (отбрасывание уже начатого распознавания) проверено только чтением кода, без автотеста.
- Изменение настроек дока (значки, увеличение, стекло) из его собственного окна настроек попадает в окно Jarvis при следующем чтении — когда Plasma запишет свои файлы (обычно через несколько секунд) и пока открыт раздел «Рабочий стол»; обратное направление (из окна Jarvis в док) — сразу.
- Не проверено вживую: экранный диктор (Orca) — подписи для него заданы (Accessible.name), но с диктором не проходили; высокая контрастность темы KDE.
- Нет и не показываются: учёт расхода токенов (Jarvis его не собирает), журнал действий (есть только статистика предложений за 30 дней), выбор микрофона внутри Jarvis (используется микрофон из настроек звука KDE, туда ведёт кнопка), собственные менеджеры звука, сети, Bluetooth и экранов.
- `desktop.dockAllScreens` по-прежнему не поддерживается и в интерфейс не выводится.
- Подписи кнопок в диалогах KDE, открываемых из Jarvis (Параметры системы, выбор файла, выбор цвета), — на языке системы: это окна KDE.
